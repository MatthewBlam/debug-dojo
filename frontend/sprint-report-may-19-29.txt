2. Impediments (Project-wise)

- Judge0 does not work on macOS Docker — Our code execution engine, Judge0, only runs reliably in Docker on Linux. The team spent significant time trying to get it working locally on macOS without understanding why it was failing. After I investigated, I discovered this is a known limitation — Judge0's Docker setup relies on Linux-specific features (cgroups, isolate sandboxing) that don't translate through Docker Desktop's macOS VM layer. This blocked local backend testing for anyone on a Mac and delayed our ability to validate the submission pipeline end-to-end.

3. Team Issues

- Negative/Challenge: Splitting up work across the team was sometimes difficult. A concrete example: two different team members independently set up separate Supabase projects — one for the problems/submissions tables and another for authentication. We had to reconcile and consolidate these into a single Supabase project, which took extra coordination effort. Going forward, we've aligned on using one shared project.
